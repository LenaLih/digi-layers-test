# Map Layers Control

Тестовое задание для позиции Frontend Developer.

Интерактивный интерфейс для работы с картографическими слоями на React + TypeScript с использованием Vedro, MapLibre GL и Recharts.

## Demo

[Открыть приложение](https://lenalih.github.io/digi-layers-test/)

## Функциональность

Реализованы три пользовательских слоя:

- Температура
- Ветер
- Инсоляция

Для каждого слоя доступны:

- включение и выключение;
- регулировка прозрачности;
- состояния `idle / loading / success / error`;
- повторная загрузка после ошибки;
- асинхронная загрузка mock-данных;
- отображение данных непосредственно на карте;
- отображение временного ряда на графике.

Также реализованы:

- общий timeline `10:00–14:00`;
- синхронизация timeline, карты и графиков;
- изменение карты при переключении времени;
- выбор времени кликом по графику;
- popup с данными при наведении на объект карты;
- кэширование уже загруженных данных по времени;
- защита от race condition при быстрых переключениях;
- обработка отмены запросов через `AbortController`.

### `entities/layer`

Содержит доменную модель картографического слоя:

- типы;
- конфигурацию слоёв;
- Vedro store;
- mock-данные;
- mock API;
- UI отдельного слоя.

### `features/layer-control`

Содержит действия пользователя:

- включение и выключение слоя;

- управление асинхронными запросами;

### `widgets/map`

Инкапсулирует интеграцию с MapLibre GL.

Конфигурация визуального представления слоёв вынесена отдельно в `mapLayerConfig.ts`, поэтому данные слоя не зависят от конкретной реализации карты.

### `widgets/analytics`

Содержит графики временных рядов на Recharts.

`LayerChart` является универсальным компонентом и получает `layerId`, поэтому одна и та же реализация используется для разных типов слоёв.

`AnalyticsPanel` собирает графики активных слоёв.

## Управление состоянием

Глобальное состояние приложения хранится в Vedro.

Основная структура состояния:

```ts
type LayerStore = {
  layerIds: LayerId[];
  layersById: Record<LayerId, Layer>;
  selectedTime: Time;
  seriesById: Record<LayerId, LayerSeriesPoint[]>;
};
```

Слои хранятся в нормализованном виде:

```ts
layersById: Record<LayerId, Layer>
```

Каждый слой содержит данные, сгруппированные по времени:

```ts
dataByTime: Partial<Record<Time, LayerGeoJson>>;
```

Это позволяет:

- получать слой напрямую по `id`;
- хранить данные нескольких временных точек;
- повторно использовать уже загруженные данные;
- не выполнять новый запрос при возврате к уже загруженному времени;
- централизованно синхронизировать карту и UI.

## Синхронизация timeline, карты и графиков

В приложении используется одно глобальное значение:

```ts
selectedTime
```

Оно является единым источником истины для выбранного момента времени.

Поток данных выглядит следующим образом:

```text
Timeline / click по графику
            ↓
       changeTime()
            ↓
     Vedro selectedTime
        ↓          ↓
      Map        Charts
```

При смене времени:

1. обновляется `selectedTime`;
2. для включённых слоёв запускается загрузка данных нового временного среза;
3. полученные GeoJSON-данные сохраняются в `dataByTime`;
4. карта получает данные для текущего времени;
5. графики отображают то же выбранное время через `ReferenceLine`.

Клик по точке времени на любом графике использует тот же `changeTime()`, поэтому изменение также синхронизируется с timeline и картой.

## Карта

Для карты используется **MapLibre GL**.

Причины выбора:

- open-source;
- поддерживает WebGL;
- хорошо работает с GeoJSON;
- предоставляет API для динамического добавления источников и слоёв;
- позволяет изменять данные без пересоздания карты;
- подходит для большого количества динамических GIS-слоёв.

Карта создаётся один раз.

При изменении состояния React не пересоздаёт экземпляр MapLibre — обновляются только данные существующих GeoJSON sources:

```ts
source.setData(data);
```

Также отдельно меняются:

- `visibility`;
- `circle-opacity`.

## Визуализация слоёв

Настройки отображения вынесены в:

```text
widgets/map/model/mapLayerConfig.ts
```

Например, температура может менять цвет в зависимости от значения, ветер — размер маркера, а инсоляция — интенсивность цвета.

Таким образом:

```text
данные
  ↓
GeoJSON { value }
  ↓
mapLayerConfig
  ↓
MapLibre visualization
```

Доменная модель при этом не содержит MapLibre-специфичных настроек.

## Графики

Для визуализации временных рядов используется Recharts.

`LayerChart` универсален:

```tsx
<LayerChart layerId="temperature" />
```

Данные графика берутся из Vedro:

```ts
state.seriesById[layerId]
```

А не напрямую из UI констант.

Таким образом карта, timeline и графики используют общее состояние приложения.

## Асинхронная загрузка

Mock API имитирует реальный сетевой запрос с задержкой.

Успешный сценарий:

```text
idle
  ↓
loading
  ↓
success
```

Сценарий ошибки:

```text
idle
  ↓
loading
  ↓
error
```

После ошибки пользователь может повторить запрос.

Mock API также специально содержит вероятность ошибки, чтобы можно было проверить обработку `error`.

## Кэширование данных

Загруженные значения сохраняются по времени:

```ts
dataByTime[time]
```

Перед новым запросом проверяется наличие данных:

```ts
if (currentLayer.dataByTime[time]) {
  // используем кэш
  return;
}
```

Например:

```text
10:00 → запрос
11:00 → запрос
12:00 → запрос
10:00 → данные уже есть, новый запрос не нужен
```

Это уменьшает количество лишних запросов и ускоряет повторное переключение timeline.

## Race condition

При быстром переключении времени может возникнуть ситуация:

```text
10:00 → request A
11:00 → request B
14:00 → request C
```

При этом более старый запрос потенциально может завершиться позже нового.

Для защиты используются два механизма.

### AbortController

Для каждого слоя хранится текущий `AbortController`.

При запуске нового запроса предыдущий запрос этого слоя отменяется:

```ts
controllers.get(id)?.abort();

const controller = new AbortController();

controllers.set(id, controller);
```

### requestId

Каждому запросу назначается уникальный идентификатор:

```ts
const requestId = crypto.randomUUID();
```

Перед сохранением ответа проверяется:

```ts
if (latestLayer.requestId !== requestId) {
  return;
}
```

Поэтому устаревший запрос не может перезаписать данные более нового запроса.

Использование одновременно `AbortController` и `requestId` даёт защиту как на уровне транспорта, так и на уровне состояния приложения.

## Состояние карты во время загрузки

При переключении на время, данные которого ещё не получены, карта не продолжает показывать устаревшие данные предыдущего временного среза.

GeoJSON source временно получает пустую коллекцию:

```text
{
  type: 'FeatureCollection',
  features: [],
}
```

После завершения запроса MapLibre получает актуальные данные выбранного времени.

## Масштабирование

Основная логика не привязана к конкретному количеству слоёв.

Список слоёв формируется из конфигурации:

```ts
export const layerConfigs = [
  {
    id: 'temperature',
    title: 'Температура',
  },
  {
    id: 'wind',
    title: 'Ветер',
  },
  {
    id: 'insolation',
    title: 'Инсоляция',
  },
];
```

UI строится по `layerIds`, а универсальные компоненты получают `layerId`.

Для нового слоя необходимо добавить:

- конфигурацию слоя;
- источник/mock-данные;
- при необходимости конфигурацию его визуализации на карте.

При этом основную бизнес-логику `useLayerActions`, timeline и универсальный `LayerChart` менять не требуется.

В production-приложении метаданные и данные слоёв могут приходить с backend API.

## Производительность

В решении используются:

- нормализованное состояние `layersById`;
- обновление конкретного объекта слоя;
- один экземпляр MapLibre;
- обновление GeoJSON через `source.setData`;
- кэширование данных по времени;
- отмена устаревших запросов;
- универсальные компоненты, работающие по `layerId`.

Для значительно большего количества слоёв дополнительными направлениями оптимизации могут быть виртуализация длинной панели слоёв и более granular-подписки на store.

## UI

Для интерфейса используется Material UI.

Map popup также рендерится как React/MUI-компонент внутри MapLibre через `createRoot` и `setDOMContent`.

Это позволяет сохранять единый стиль интерфейса без формирования UI через HTML-строки.
