# Map Layers Control

Тестовое задание для позиции Frontend Developer.

Интерфейс управления картографическими слоями на React + TypeScript с использованием Vedro.

## Функциональность

Реализовано управление тремя слоями:

- Температура
- Ветер
- Инсоляция

Для каждого слоя доступны:

- включение и выключение;
- регулировка прозрачности;
- отображение статуса `idle / loading / success / error`;
- повторная загрузка после ошибки;
- имитация API-запроса;
- защита от race condition при быстрых переключениях.

## Стек

- React
- TypeScript
- Vite
- Vedro
- Material UI

## Управление состоянием

Для глобального состояния используется Vedro.

Состояние хранится в нормализованном виде:

```ts
type LayerStore = {
  layerIds: LayerId[];
  layersById: Record<LayerId, Layer>;
};
```

Такой подход позволяет:

- быстро получать слой по `id`;
- не выполнять поиск по массиву при каждом обновлении;
- обновлять только конкретный слой;
- удобно масштабировать состояние.

Каждый `LayerItem` подписывается только на состояние своего слоя:

```ts
const { layer } = useLayerStoreSelector((state) => ({
  layer: state.layersById[id],
}));
```

Поэтому изменение одного слоя не вызывает повторный рендер остальных компонентов.

Во время разработки это дополнительно проверялось через `console.count`.

## Производительность

Для работы с большим количеством слоёв используются:

- нормализованное состояние через `layersById`;
- подписка компонента только на конкретный слой;
- `React.memo` для `LayerItem`;
- обновление только изменяемого объекта слоя;
- отсутствие зависимости UI одного слоя от состояния остальных.

## Масштабирование

Конфигурация слоёв отделена от store:

```ts
export const layerConfigs = [
  { id: 'temperature', title: 'Температура' },
  { id: 'wind', title: 'Ветер' },
  { id: 'insolation', title: 'Инсоляция' },
];
```

Чтобы добавить новый слой, достаточно добавить новую конфигурацию:

```text
{
  id: 'humidity',
  title: 'Влажность',
}
```

Компоненты и бизнес-логика при этом не меняются.

Такой подход позволяет масштабировать решение до 100+ слоёв.

В реальном приложении конфигурация слоёв также может приходить с backend API.

## Асинхронная загрузка

При включении слоя выполняется mock API-запрос.

Успешный сценарий:

```text
idle
↓
loading
↓
success
```

Сценарий с ошибкой:

```text
idle
↓
loading
↓
error
```

После ошибки пользователь может повторить загрузку.

Mock API специально имеет вероятность ошибки, чтобы можно было проверить обработку состояния `error`.

## Race condition

При быстрых переключениях слоя может возникнуть ситуация, когда старый запрос завершится позже нового и попытается записать устаревшее состояние.

Для защиты используются два механизма.

### AbortController

Для каждого слоя хранится собственный `AbortController`.

При запуске нового запроса предыдущий запрос этого слоя отменяется:

```ts
controllers.get(id)?.abort();

const controller = new AbortController();
controllers.set(id, controller);
```

### requestId

Каждому запросу присваивается уникальный `requestId`:

```ts
const requestId = crypto.randomUUID();
```

Перед применением результата проверяется, что завершившийся запрос всё ещё является актуальным:

```ts
const currentLayer = store.get('layersById')[id];

if (currentLayer.requestId !== requestId) {
  return;
}
```

Даже если устаревший запрос завершится позже нового, его результат не перезапишет актуальное состояние слоя.

## Mock API

Mock API имитирует сетевой запрос с задержкой и поддерживает отмену через `AbortSignal`.

```ts
await new Promise<void>((resolve, reject) => {
  const timeoutId = window.setTimeout(resolve, 1000);

  signal?.addEventListener(
    'abort',
    () => {
      window.clearTimeout(timeoutId);

      reject(
        new DOMException(
          'Request aborted',
          'AbortError',
        ),
      );
    },
    { once: true },
  );
});
```

Для проверки обработки ошибок используется случайная ошибка:

```ts
if (Math.random() < 0.25) {
  throw new Error('Layer loading failed');
}
```

## UI

Для интерфейса используется Material UI.

Для каждого слоя отображаются:

- название слоя;
- switch включения;
- slider прозрачности;
- текущий статус;
- кнопка повторной загрузки при ошибке.


API Vedro дополнительно проверялся по установленному пакету и его TypeScript declarations.

Перед использованием store API были проверены реальные методы Vedro:

```text
get(): S;

get<K extends keyof S>(
  key: K,
): S[K];
```

После этого код был адаптирован под фактический API библиотеки.
